# Wireshark: Traffic Analysis

## Scenario Overview

This lab focuses on analysing multiple packet captures using **Wireshark** to identify network reconnaissance, credential theft, protocol abuse, tunnelling techniques and web-based attacks.

Throughout the investigation, different protocols and attack scenarios are analysed to simulate the workflow of a SOC analyst performing network traffic investigations.

---

## Objectives

- Analyse packet captures using Wireshark display filters.
- Identify malicious network activity across multiple protocols.
- Detect reconnaissance and Man-in-the-Middle (MITM) attacks.
- Investigate cleartext and encrypted network communications.
- Extract Indicators of Compromise (IOCs).
- Generate actionable findings from captured traffic.

---

# Nmap Scan Analysis

## Background

Nmap is one of the most widely used network discovery tools. Understanding the traffic generated by different scan types allows analysts to distinguish legitimate reconnaissance from potentially malicious scanning activity.

This section focuses on identifying:

- TCP Connect Scans
- SYN Scans
- UDP Scans

---

## Evidence Analysis

### TCP Connect Scan Detection

The following display filter was applied:

```text
tcp.flags.syn == 1 and tcp.flags.ack == 0 and tcp.window_size > 1024
```

The analysis identified **1000 TCP Connect Scan packets**, indicating active host discovery.

![TCP Connect Scan](images/TCP-Connect.png)

---

### UDP Scan Detection

To identify closed UDP ports, the following filter was applied:

```text
icmp.type == 3 and icmp.code == 3
```

Analysis revealed **1083 ICMP Port Unreachable** messages.

Further investigation identified **UDP port 68** as the only open port within the specified range.

![UDP](images/UDP.png)

# ARP Spoofing Analysis

## Background

ARP does not provide authentication, making it vulnerable to spoofing attacks that allow adversaries to position themselves as a Man-in-the-Middle (MITM).

---

## Evidence Analysis

### Detecting ARP Spoofing Activity

The following filter was applied:

```text
arp.dst.hw_mac==00:00:00:00:00:00 and arp.src.hw_mac==00:0c:29:e2:18:b4
```

Analysis identified **284 malicious ARP requests** generated by the same MAC address.

![ARP Requests](images/ARP-spoofing.png)

---

HTTP traffic destined for the attacker's MAC address was then isolated.

```text
eth.dst==00:0c:29:e2:18:b4 and http
```

The capture contained **90 HTTP packets**, confirming successful traffic interception.

![HTTP Packets](images/HTTP.png)

---

Credential theft was confirmed using:

```text
(eth.dst==00:0c:29:e2:18:b4 and http) && (urlencoded-form.key=="pass")
```

Six username/password submissions were identified.

Recovered credential:

Password: `clientnothere!`

The investigation also revealed the user comment:

"Nice work!"

![Credentials](images/Credentials.png)

# Host Identification

## Background

DHCP, NetBIOS and Kerberos provide valuable metadata that allows analysts to identify users and hosts during investigations.

---

## Evidence Analysis

### DHCP Analysis

The following filter was applied:

```text
dhcp.option.hostname contains "Galaxy"
```

The MAC address associated with **Galaxy A30** was identified.

**MAC Address:** `9a:81:41:cb:96:6c`

The device requesting IP address **172.16.13.85** was identified as:

**Galaxy-A12**

![DHCP](images/DHCP.png)

---

### NetBIOS Analysis

Using:

```text
nbns.name contains "LIVALJM" and nbns.flags.opcode==5
```

Analysis revealed **16 NetBIOS registration requests**.

![NetBIOS](images/Netbios.png)

---

### Kerberos Analysis

Using:

```text
kerberos.CNameString contains "u5"
```

The user **u5** was associated with:

**IP:** `10[.]1[.]12[.]2`

Further inspection identified the workstation:

**xp1$**

# ICMP & DNS Tunnelling

## Background

Trusted protocols such as ICMP and DNS can be abused to establish covert communication channels for Command and Control (C2) or data exfiltration.

---

## Evidence Analysis

### ICMP Tunnelling

Inspection of ICMP payloads revealed encapsulated **SSH traffic**, confirming the use of ICMP as a covert communication channel.

![ICMP](images/ICMP.png)

---

### DNS Tunnelling

DNS traffic was analysed using:

```text
dns
```

Inspection of the **Queries Name** field identified repeated queries directed to:

> `dataexfil[.]com`

Packet inspection also revealed encapsulated **SSH data**.

![DNS](images/DNS.png)

# FTP Investigation

## Background

FTP transmits authentication credentials and commands in plaintext, making it a valuable source of forensic evidence.

---

## Evidence Analysis

### Failed Authentication Attempts

Using:

```text
ftp.response.code == 530
```

The investigation identified **737 failed login attempts**, suggesting a brute-force attack.

![FTP Failed Logins](images/FTP-Failed-Logins.png)

---

Successful authentication was identified using:

```text
ftp.response.code == 230
```

The TCP Stream revealed interaction with:

- File: `resume.doc`
- Size: **39,424 bytes**

Further inspection showed the command:

```text
CHMOD 777
```
![TCP Stream](images/TCP-Stream.png)
